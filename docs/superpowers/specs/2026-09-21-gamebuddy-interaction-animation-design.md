# GameBuddy 交互、动态形象与气泡排版设计

日期：2026-09-21  
需求提出人：恒祥

## 1. 目标

在不改变 OCR、推荐算法、LCU/Live Client 数据链路和 C++ 视觉引擎的前提下，增强 GameBuddy 小猫 Overlay：

1. 小猫区域支持右键打开单项“退出”菜单。
2. 小猫区域支持左键长按 500ms 后拖动整个 Overlay。
3. 小猫根据业务状态播放持续循环的动态形象。
4. 气泡文本避免换行后仅剩 1～2 个字符。
5. 推荐类结构化文本使用普通标题和粗体内容。

## 2. 范围边界

### 2.1 包含

- `scripts/product/cat_overlay.py` 中与窗口展示、鼠标命中和绘制有关的最小改动。
- 独立的动画播放、状态映射、拖动边界和富文本布局模块。
- `assets/gamebuddy/` 下的透明 PNG 动画帧及清单。
- `ProductController` 输出可选的结构化展示字段，同时保留原有纯文本字段。
- 本需求对应的聚焦自动化测试和 Windows 人工验收清单。

### 2.2 不包含

- OCR 识别策略、推荐算法、英雄或海克斯数据调整。
- LCU、Live Client 和 C++ 视觉引擎逻辑修改。
- 保存用户拖动位置。
- 气泡、文字或玩法按钮的动画。
- 为动画引入 Pillow 等新的运行时第三方依赖。

## 3. 现有行为约束

- Overlay 是无边框、置顶且不抢占游戏焦点的 Windows 窗口。
- 当前只有玩法、分页和重试区域接受点击，其余区域点击穿透到游戏。
- 小猫短点击在允许重试时触发现有重新识别逻辑。
- 新增交互不能扩大透明区域的鼠标拦截范围，也不能改变上述短点击行为。

## 4. 动画状态模型

动画层只读取现有展示状态，不参与业务判断。状态变化时立即中断旧循环并切换到新动画。

| 动画状态 | 设计稿姿态 | 业务触发 |
| --- | --- | --- |
| `idle` | 闭眼、呼吸 | 气泡隐藏、等待下一轮或无操作 |
| `greeting` | 举手摇爪 | 程序首次显示，或气泡由隐藏变为显示 |
| `thinking` | 挠头 | `ocr_reading`、`ocr_confirming`、`ocr_updating` |
| `listening` | 歪头 | 选英雄阶段，或新一轮三选一刚出现时的短暂观察阶段 |
| `success` | 点爪、点头 | 推荐结果正常产生并显示 |
| `failure` | 耳朵下垂 | OCR 错误、推荐数据不足、模式不支持或视觉引擎异常 |

`greeting` 是短暂业务状态，默认播放约 1.2 秒后按当前业务状态继续。新一轮三选一首次出现时，
`listening` 默认播放约 0.6 秒，再进入 `thinking`。除这两个明确的过渡状态外，其余状态持续循环，
直到业务状态变化。

状态优先级为：`failure` > `thinking` > `success` > `listening` > `greeting` > `idle`。优先级只用于同一快照出现多个信号时消除歧义。

## 5. 动画资源与播放器

### 5.1 资源组织

```text
assets/gamebuddy/
  animations.json
  idle/*.png
  greeting/*.png
  thinking/*.png
  listening/*.png
  success/*.png
  failure/*.png
```

- 每帧使用透明背景 PNG，显示尺寸与当前约 112px 的小猫区域兼容。
- `animations.json` 声明状态、帧顺序、单帧时长和是否循环。
- 默认目标帧率约 10 FPS，可通过不同帧时长降低静态状态的更新频率。
- Ardot 中的六张姿态是角色造型和状态语义的依据。
- 优先通过轻微纵向拉伸、横向压缩、上下位移和摆动生成过渡帧。
- 仅当程序变形不足以表达动作时，才补充同风格透明 PNG；皇冠、耳朵、眼睛、项圈和配色必须一致。

### 5.2 运行时

- 新增独立动画播放器，负责加载清单、缓存 `PhotoImage`、调度下一帧和立即切换状态。
- Tk 主线程通过 `after` 调度切帧，不创建额外 UI 线程。
- 动画只更新小猫画布项，不触发气泡重新布局。
- 拖动期间冻结当前帧，松手后从当前业务状态恢复循环。
- 资源、清单或单帧加载失败时记录日志，并回退到现有 `assets/gamebuddy-cat.png`。
- 回退不得阻止 Overlay、识别或推荐功能启动。

## 6. 右键退出菜单

- 右键仅在小猫实际显示矩形内生效。
- 使用小型上下文菜单显示唯一菜单项“退出”，位置贴近右键点击点并保持在屏幕内。
- 点击“退出”立即调用现有关闭链路，停止轮询、视觉子进程和窗口。
- 点击菜单外、按 Escape 或再次右键时仅收起菜单。
- 不显示“是否退出 GameBuddy？”二次确认框。
- 气泡、按钮外区域和透明区域继续点击穿透。

## 7. 长按拖动

- 左键在小猫区域按下后启动 500ms 计时。
- 500ms 内松开视为短点击，继续执行现有重试识别行为。
- 达到 500ms 且仍按下时进入拖动；鼠标移动带动整个 Overlay，气泡和按钮保持相对位置。
- 松开鼠标、窗口关闭或捕获丢失时结束拖动并清理状态。
- 拖动位置只存在内存中，应用重启后恢复默认右上角。
- 根据当前显示器工作区限制窗口位置，至少保证小猫完整可见。
- 拖动命中与现有玩法、分页按钮命中分离，按钮操作不触发拖动。

## 8. 气泡换行

- 介绍、玩法名、推荐正文、错误提示等全部气泡文本使用统一测量换行逻辑。
- 保留原始段落和全部字符。
- 继续避免句号、逗号、右括号等结束标点出现在新行行首。
- 某段末行只有 1～2 个字符时，从上一行回退足够字符，使末行至少有 3 个字符。
- 如果可用宽度连 3 个字符都无法容纳，则以“当前宽度能容纳”为硬限制，禁止产生无限重排。
- 分页必须基于重排后的行高计算，不能导致文字覆盖按钮或超出屏幕。

## 9. 标题与内容字重

`ProductController` 在保留现有 `message` 纯文本的同时，增加可选的结构化文本段。Overlay 优先使用结构化字段绘制，缺失时走原纯文本兼容路径。

以下结构化行统一使用“标题普通、内容粗体”：

- `当前推荐` + 推荐海克斯和位置
- `当前玩法` + 玩法名称
- `所需海克斯` + 海克斯列表或“无固定组合”
- `所需装备` + 装备列表或“无固定出装要求”

富文本布局器按实际字体宽度排列多个文本片段，并与统一孤行规则、分页规则共用行布局结果，不能通过解析最终展示字符串猜测标题。

## 10. 模块边界

建议新增以下小模块，避免继续扩大现有 `cat_overlay.py`：

- `cat_animation.py`：动画清单、帧缓存、状态切换和帧调度。
- `overlay_interaction.py`：小猫命中、长按状态机和屏幕边界计算中的纯逻辑。
- `rich_text_layout.py`：结构化文本、字体测量、换行、孤行平衡和分页。

`cat_overlay.py` 只负责把这些模块接到 Tk/Win32 事件和画布上。新增方法遵守单个方法不超过 80 行、单行不超过 120 字符，并且不进行需求外重构。

## 11. 错误处理

- 动画资源错误：记录文件与状态，回退静态图。
- 动画回调异常：停止该动画循环，保留最后有效帧或静态图，不退出应用。
- 右键菜单创建失败：记录错误，Overlay 继续运行，Escape 关闭仍保留。
- 拖动捕获丢失：立即结束拖动，恢复动画和正常命中。
- 富文本字段异常：回退现有纯文本 `message`。

## 12. 自动化验证

聚焦测试覆盖：

1. 六种业务状态映射、优先级和立即切换。
2. 帧循环、拖动冻结、恢复及资源错误回退。
3. 500ms 长按阈值、短点击兼容、拖动起止和捕获丢失。
4. 当前显示器边界计算，保证小猫完整可见。
5. 右键菜单打开、收起和“退出”回调。
6. 全部气泡文本的换行、标点保护和末行至少 3 字符。
7. 结构化标题普通、内容粗体及纯文本回退。
8. Python 编译、动画清单与全部 JSON 解析、现有启动入口导入。

## 13. Windows 人工验收

实现和自动化测试完成后，由用户在 Windows 实机执行并反馈：

1. 右键小猫出现仅含“退出”的小菜单；右键其他区域不出现。
2. 点击菜单外可收起；点击“退出”后程序及视觉子进程结束。
3. 短按小猫不拖动，仍可在允许时触发重试。
4. 长按不足 500ms 不拖动；达到 500ms 后可以平滑拖动整个 Overlay。
5. 小猫不能被拖出当前显示器；重启后恢复默认位置。
6. 六种状态分别持续循环，业务状态变化时立即切换。
7. 拖动时动画冻结，松手后恢复；气泡和按钮本身不变形。
8. 气泡没有仅剩 1～2 字符的末行，也没有行首结束标点。
9. 结构化标题为普通字重，标题后的值为粗体。
10. 动画资源故意缺失时仍能以原静态小猫启动并使用推荐功能。

Windows 实机结果返回前，交付状态只能表述为“代码及自动化验证完成，Windows 实机待验收”。
