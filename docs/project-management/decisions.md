# 关键决策

更新时间：2026-09-21

详细依据见
[GameBuddy Windows Overlay 修订与语音陪伴设计](../superpowers/specs/2026-09-21-gamebuddy-windows-overlay-voice-design.md)。

## DEC-001：猫咪绝对坐标是位置真相

- 决策：用虚拟桌面绝对矩形保存猫咪位置，允许负横纵坐标。
- 原因：Tk 的负位置字符串表示距右边或下边的偏移，会造成左侧屏幕镜像和跳边。
- 影响：Windows 用 `SetWindowPos` 移动组合窗口，Tk `geometry` 只负责尺寸。

## DEC-002：按候选猫咪中心选择显示器

- 决策：拖动时使用候选猫咪中心点选择目标显示器，再读取其实际工作区。
- 原因：使用鼠标位置会在猫咪尚未跨屏时提前切换工作区并产生吸附。
- 影响：边界限制只保证猫咪完整位于目标工作区，不硬编码分辨率。

## DEC-003：保留单个透明窗口

- 决策：猫咪、气泡和按钮继续绘制在一个透明 Overlay 窗口中。
- 原因：避免拆分窗口带来的置顶、焦点、点击穿透和关闭生命周期问题。
- 影响：每次重排取猫咪和气泡矩形并集，但不修改猫咪绝对矩形。

## DEC-004：气泡内容自适应，约 780px 只是上限

- 决策：按文本和控件测量气泡宽度，短内容收缩，长内容最大有效宽度约 780px。
- 原因：固定宽度会让短气泡留下大量空白；窄宽度又会过早换行。
- 影响：保留完整内容和孤字保护，不分页、不滚动、不缩字、不自动摘要显示文本。

## DEC-005：边缘气泡向可用空间重排

- 决策：四边使用相反方向，四角使用斜对角，中心选择完整容纳且余量最大的方向。
- 原因：在边缘压缩或分页会破坏阅读，并会错误牵动猫咪位置。
- 影响：气泡内容改变只更新气泡和根窗口，不反向写入猫咪坐标。

## DEC-006：五种批准姿态承担全部产品状态

- 决策：等待与选英雄复用歪头；OCR 与拖动复用抓头；其他状态使用对应批准姿态。
- 原因：保持角色一致性，并移除从旧合成图中带入的 Codex 宠物。
- 影响：各状态约每 3 秒眨眼，动作只改变允许运动的局部肢体。

## DEC-007：语音采用统一消息模型和可插拔适配器

- 决策：本地事件与未来远端消息统一为 `SpeechMessage`，业务层不直接调用 TTS。
- 原因：把摘要、优先级、去重、过期和播放实现分离，便于后续替换语音后端。
- 影响：首版完成本地链路，只保留远端适配边界，不新增远端网络访问。

## DEC-008：首版使用持久 Windows `System.Speech` worker

- 决策：一个长期运行的 PowerShell 子进程加载 `.NET System.Speech`。
- 原因：避免每条语音重复启动 PowerShell，并保持首版无新增 Python 运行时依赖。
- 影响：worker 初始化或播放失败必须静默降级，不能阻塞 UI、OCR、推荐或退出。

## DEC-009：语音开关持久化并立即生效

- 决策：语音默认开启，右键菜单动态切换，配置写入 `overlay.json`。
- 原因：用户需要随时控制陪伴播报，且重启后保持选择。
- 影响：关闭时取消当前播放、拒绝新消息并清理低优先级队列。
