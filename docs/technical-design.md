# GameBuddy 小猫 UI 与推荐逻辑技术方案

## 产品范围

本仓库以 2026-09-15 OCR 快照为基线。OCR 负责英雄、三选一候选、轮次和最终选择识别；本次只新增：

1. 选人阶段对当前英雄与待选席给出胜率/趣味建议，并提供三种局内策略入口；
2. 胜率池与趣味玩法池推荐；
3. 右上角小猫及气泡展示；
4. 策略状态持久化和已选海克斯联动。

推荐只出现在小猫气泡，不描边、高亮或覆盖游戏原生卡牌。

## 已有接口

`RecognitionViewModel.snapshot()` 提供：

- `match_id`：本局 ID；
- `champion`：英雄中文名；
- `offer`：三张 `{slot, augment_id, name}`；
- `offer_round`：第 1～4 轮；
- `selected`：已确认选择 `{stage, augment_id, name, slot, source}`；
- LCU、Live Client 和视觉健康状态。

已选记录继续追加到 `%LOCALAPPDATA%\LoLRecognitionOverlay\selected_hexcores.jsonl`。产品层只新增 `strategy.json`，不复制 OCR 历史。

## 数据审计与处理

- 趣味玩法池：274 条、145 个英雄；65 个英雄只有 1 套，29 个胜率池英雄没有趣味玩法。
- 胜率池：172 个英雄、19,706 条英雄/海克斯记录；名称均可映射到知识库。
- 知识库：223 张，216 张启用；推荐过滤 7 张未启用海克斯。
- 玩法列表通常为 2～4 张，但有 2 条为 5/6 张；加载器不截断，以保持原始体系。
- 有 4 组同英雄同名玩法，按 `S > A`、更新时间降序去重。
- 跨池英雄名存在空格和间隔点差异，使用仅消除排版标点的规范化键，不猜测翻译。
- 趣味池未显式标识核心海克斯。MVP 将有序列表前两张视为核心，其余视为搭配；未来增加显式字段时只替换 `FunPlan.core_augments`。

## 决策规则

### 胜率优先

三张候选按当前英雄的海克斯胜率降序；同胜率依次按场次降序、源排名升序、槽位顺序稳定排序。

选人阶段候选集为当前英雄与待选席的并集：输出英雄胜率最高项；趣味玩法先取更新时间最近的 10 条，再按本局 ID 稳定随机选最多 3 条。

### 趣味玩法

1. 候选命中尚未获得的核心海克斯：按玩法列表顺序推荐；
2. 未命中核心但命中体系搭配：按玩法列表顺序推荐；
3. 均未命中：回退当前英雄已识别候选中胜率最高项，气泡用「哎呀，玩法需要的核心没有抽到」类话术说明回退。

用户没有采纳推荐时，以 OCR 实际识别的 `selected` 为准，不篡改历史。

## UI 状态

- 无英雄：小猫等待；
- 已识别英雄、未选策略：气泡展示胜率优先、趣味玩法 1、趣味玩法 2；
- 玩法不足：对应入口不可用并说明数据不足，不伪造玩法；
- 三选一：仅气泡展示一张“推荐名称 + 左/中/右位置 + 理由”；
- 识别不足三张：在已识别候选中降级推荐并说明可点击猫咪刷新；一张都没有时只展示刷新引导；
- 选牌后：显示已记录数量并等待下一轮。

猫咪区域可点击并向已有视觉进程发送重读信号。UI 不模拟游戏输入。

## 失败边界

- 局内 Live Client 模式不是 `ARAM`，或启动识别模式不是 `KIWI/KIWI_JADE`：不推荐；
- 候选不完整：只在已通过白名单的 1～2 张中降级推荐；
- 策略不可用：不保存；
- 胜率缺失：已知候选优先；三张均缺失时稳定选择左侧并明确不展示伪造胜率；
- 数据文件损坏：启动失败并报告数据错误，不以空池运行；
- UI 不可用不会改变 OCR 识别与历史文件。

## 已记录、本轮不启用的数据规则

- 海克斯场次 `>= 200` 才可作为充分样本首选，`80～199` 显示「样本不足」；
- 跨一个游戏版本的数据需要降权；
- 两项待产品确认口径后再开启，当前仍保持原胜率排序。
